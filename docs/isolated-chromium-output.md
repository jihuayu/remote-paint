# 显式 Chromium 输出目录与收据绑定

prepare、Mac构建包装器、Linux输入检查/收据和打包必须显式传入 --output out/name。共同解析器只接受out下的单个名称，拒绝绝对路径、目录穿越、多层路径、空值及额外字符；解析目录只读，检查source、out及所选目录的符号链接和非目录节点，保留已选目录中的对象缓存。名称本身不构成隔离保证，调用方必须选择自己拥有的目录。CI显式选择既有缓存名称，本地新任务应选择自己的新名称；本任务未访问本机禁止的旧输出或演示容器。

prepare不再自动探测另一平台的默认输出目录。已准备源码迁移到新目录时，使用 --patch-state-from out/previous 显式导入受信任的补丁收据；缺失、未知条目或冲突哈希会失败。该清单不独立证明实际源码已应用，真实构建仍须核验patchedSources和执行验收。GN、Ninja、测试程序、收据、license生成及package入口传递同一选择。CI的Docker环境、缓存路径和诊断上传也使用同一变量；既有CI默认值不变，保留其缓存布局。

新生成的Linux收据为format2，记录outputDirectory。打包必须用所选目录匹配该字段，不能用未绑定目录的旧收据制作新包。format1保留历史运行时数据的校验能力；缺少输出参数的检查/生成API与CLI均不会退回默认目录。这里没有执行真实Chromium准备、编译、CI或发布打包，也未证明当前大量未提交源码已被发行清单完整收录。

新增10项合同覆盖严格目录选择、只读解析、已有缓存inode/mtime/字节保留、目录符号链接拒绝、文件拒绝覆盖、API/四CLI缺省拒绝、实际临时目录的输入检查路由、显式补丁状态导入及冲突/未知条目拒绝。夹具只伪造git的revision回答，用真实Node与文件系统执行路由，禁止伪造git apply；不冒充真实Chromium或浏览器验收。相关13项首轮全通过。最终冻结1139文件候选执行139根文件1435项JS双平台回归：Mac1420通过15平台跳过，Linux1429通过6跳过，均退出0；3个shell、7个JS语法检查及YAML/变量传播共11项均退出0。首候选通过后发现CI缓存/诊断仍是字面路径，仅改该workflow并冻结第二候选，最终两平台重新全量执行，保留两版原始结果。
