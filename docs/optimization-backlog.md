# Remote Paint 客户端 SDK 与服务器优化清单

当前优先投入应是消除客户端整屏像素读回、解除公网逐帧等待 ACK 的限制、减少每次采集的 CDP 往返，以及降低重复场景元数据和缓存抖动。继续把普通控制逻辑从 JavaScript 改为原生代码，通常没有这几项直接。

云端任务、Agent 执行、账号与凭据、隔离、计费和上线顺序另见[云 Agent 产品路线](cloud-agent-product.md)。

当前最小 WebGL2 页面已实测：源端渲染正常，但资源映射缺失导致整帧未提交。C12 和 B13 的混合回退是实际兼容缺口，详见 [WebGL 诊断](webgl-boundary.md)。

本清单以 2026 年 10 月 16 日的完整 Linux ARM64 与 Mac Viewer 验收为基线。以下条目是后续工作，不代表已经实现或已经获得性能收益。P0 表示下一轮重点或上线前置条件，P1 表示扩大使用后应完成，P2 表示经测量后再投入。

## 当前数据与代码边界

| 项目 | 当前结果 | 使用范围 |
| --- | --- | --- |
| 真实输入到 Mac CanvasKit 像素 | p50 48.8 ms，p95 57.8 ms | 16 次键盘输入，不含物理键盘和显示扫描 |
| 实际 Viewer 帧率 | 单人 47.6 FPS，双人各 47.1 和 47.6 FPS | 合成动画，两秒窗口 |
| 每个 Viewer 下行 | 约 0.98 至 1.02 MB/s | 同一动画场景，不是静态页面或所有网站的平均值 |
| Node CPU | 约 0.18 至 0.21 核 | 控制面仍有开销，绘图资源记录和 Viz 场景均不进入 Node |
| Rust Broker CPU | 约 0.11 至 0.12 核 | 当前一至两个 Viewer |
| Chromium CPU | 约 0.49 至 0.55 核 | 软件合成路径 |
| 单次采集快照 | captureRoundTrip 13.4 ms，map 2.36 ms | 报告末次采样，不是阶段 p50 或 p95 |
| SDK | 工程模块、脚本和浏览器协议 | 尚未形成独立发布的稳定公共 SDK |

证据见[最终验收](native-final-acceptance.md)与[正式 Mac 报告](evidence/native-mac-final.json)。不能将一个时刻的采集耗时与另一个样本的渲染耗时相加，解释端到端 p95。

动画测试单人精确流量约 1,016,504 B/s，即 8.13 Mbps。按该负载连续运行一小时外推约 3.66 GB 十进制下行；这只是持续动画负载的成本估算。浏览器内 Agent 无人观看时，不应持续支付这一整段显示流成本。

## 先建立能解释延迟的测量

应给一次交互贯穿记录 `inputSeq → captureId → sourceFrame → brokerSerial → frameId`，至少区分以下时间。不同进程、不同机器的单调时钟不能直接相减；服务器阶段使用同机时间或关联 span，客户端测完整闭环，跨机拆分还需时钟校准和误差说明。

| 阶段 | 应新增或明确的记录 | 优化用途 |
| --- | --- | --- |
| 客户端输入 | DOM 事件、排队、实际发送 | 发现输入队列等待 ACK |
| 网络上行 | 客户端发送和服务器接收关联 | 区分公网 RTT 与服务端执行 |
| 输入执行 | CDP 入队、开始、返回、目标页面代数 | 区分排队和真正注入 |
| 帧准备 | 捕获登记、BeginFrame 发出及 ACK、内容提交 | 发现多等一帧与登记顺序问题 |
| 原生工作 | 录制、编码排队、编码墙钟、IPC 发送 | 区分多线程累计工作量与关键路径 |
| Broker | Viz 和资源配对、映射、发布、发送排队 | 区分数据缺失与 Gateway 背压 |
| 客户端重放 | 接收、校验、组装、解码、合成、拷贝 | 验证 GPU 呈现和二进制协议的实际收益 |
| 呈现与业务 | 已提交画面、可用的浏览器呈现反馈、业务结果 | 分开绘图完成、用户看见和操作成功 |

至少补充 p50、p95、p99、最大帧龄、排队字节和丢弃原因。建议每个变体至少 1,000 次输入，多次独立运行，分别记录冷启动、预热、空闲唤醒和动画负载。原生编码各线程耗时之和不能作为墙钟延迟；浏览器 RAF 或 Canvas 更新也不能作为物理屏幕扫描完成的证据。

## 客户端优化

| 编号 | 优化 | 实施要点与收益 | 优先级和验收 |
| --- | --- | --- | --- |
| C1 | GPU 直接呈现 | 当前 Worker 使用 CPU raster surface，随后整屏 `readPixels → ImageData → putImageData`。增加 CanvasKit GPU surface 直接绑定 OffscreenCanvas 的路径；WebGL2 先验证，WebGPU 按 CanvasKit 实际支持再接入。需要让 pass 和 picture 缓存也适配 GPU，避免仍在 CPU 绘制后上传。 | P0，高成本。逐段测读回、复制、合成，验证文字、alpha、色彩与 context lost；CPU 路径保留回退。不能先承诺降低多少毫秒。 |
| C2 | 屏幕损伤区域重绘 | 当前复用未变的 pass，但变化的根 pass 仍可能整块重画并整屏复制。引入持久根 surface、损伤矩形与 scissor；矩阵移动同时损伤旧位置和新位置，滤镜和 backdrop 扩张依赖区域。 | P0，中高成本。小光标、单字、局部计数器不触发整屏工作；滚动、透明叠加不能残影。 |
| C3 | 取消对单个输入 ACK 的逐条等待 | `ViewerInput.pump()` 当前有一个 pending 输入，公网 RTT 会降低键盘和拖动吞吐。改为有界有序流水线；点击、按下抬起、composition 保序，连续移动可合并，滚轮按语义合并。 | P0，中成本。在 40 和 80 ms RTT 下持续输入、拖动不积压；接管撤销时旧队列全部失效。不能任意丢 keyup。 |
| C4 | 优化启动与版本缓存 | 当前静态文件普遍 `no-store`。按内容 hash 发布 CanvasKit JS、Wasm 和 Viewer，启用不可变缓存、适当压缩与预热；会话配置继续短缓存或不缓存。Wasm 流式编译需同时满足完整性和兼容校验。 | P0，中成本。分别统计首次打开、二次打开、Wasm 初始化和首帧；版本错配应明确拒绝或进入受支持回退。 |
| C5 | 管理完整客户端内存 | 对原始资源、重组 SKP、Wasm 堆、解码 picture、pass image、raster 与 GPU texture 统一记账；当前 8M 像素 raster LRU 不覆盖所有这些内存。按设备档位预算，淘汰后可正确恢复。 | P0，中成本。连续导航、resize、图片更新和 8 小时运行不出现无界增长；检查 Wasm/GPU 内存，不能只看 JS heap。 |
| C6 | 有权限边界的持久资源缓存 | 用 IndexedDB 保存不可变块和解码前资源，缩短重连首帧；缓存键包含渲染器版本与账户或租户范围。公开静态资源与私有页面内容分别处理，登出和权限撤销清理私有缓存。 | P1，中高成本。跨账号不可读取缓存；容量淘汰、版本升级和块损坏可恢复。跨租户不能仅凭内容 hash 授权。 |
| C7 | 改善指针和编辑的即时反馈 | 本地显示 cursor、hover 指示和接管状态；对受支持的文本编辑保留本地 composition 与输入预览，服务器结果负责校正。滚动预测只在已知可安全平移的场景尝试。 | P1，中成本。明确本地反馈与远端确认；密码和敏感输入不进入普通调试日志或录屏叠层。业务点击不得伪装成功。 |
| C8 | 完整 IME 与访问性 | 增加物理 macOS、Windows、Linux 和手机输入法测试，覆盖候选窗锚点、组合撤销、选区与快捷键。按授权提供受限语义层支持屏幕阅读器和焦点导航，纯 Canvas 无法自然提供这些能力。 | P0，中高成本。实际设备验证；CDP composition 成功不能替代系统候选窗验证。语义层也要遵守内容访问权限。 |
| C9 | 分辨率与设备能力自适应 | 当前源端固定 deviceScaleFactor 1。分别协商 CSS viewport、DPR、渲染分辨率和显示缩放；移动端或弱设备允许降低帧率、质量、缓存和分辨率。 | P1，中成本。Retina、旋转、缩放和输入坐标一致；DPR 翻倍可能使像素内存约四倍，不能无条件追求最高分辨率。 |
| C10 | 明确各种 ACK 的语义 | 将收到字节、校验完成、资源可用、场景提交和呈现反馈分开；服务器需要知道什么可安全复用或释放，体验指标需要知道画面何时可见。 | P0，中成本。资源不能因早 ACK 被过早释放；显示回调不能被包装成网页业务完成确认。与 B7 一起升级协议。 |
| C11 | 页面隐藏与设备故障恢复 | 标签页隐藏、设备休眠、GPU reset、Worker 崩溃时暂停或降级 Viewer，恢复后请求最新快照。区分显示消费者和仍在工作的 Agent。 | P1，中成本。隐藏后减少显示资源消耗，恢复不闪旧 epoch，不能因 Viewer 隐藏停止 Agent 所需的页面进度。 |
| C12 | 浏览器兼容与区域回退 | 验证 Chrome、Edge、Firefox、Safari、iOS 的 Worker、OffscreenCanvas、Wasm 与 GPU 能力。对视频、WebGL 和不支持的合成效果建立区域位图或视频回退。 | P0 对目标浏览器，P1 对扩展平台。区域与 SKP 共用坐标、epoch 和提交屏障，不能错位或长期不同步。 |
| C13 | 控制消息与重放队列调度 | 当前控制通知、资源组装与场景提交经过同一 Promise 队列，大资源可能拖后输入确认。按消息依赖和 epoch 设计优先队列；将可分片的解码工作分批，丢弃过期 viewport 的准备工作。SHA 校验已经并行启动，不需要重复实现。 | P1，中高成本。大字体或大图片下载和解码期间，接管和输入确认不长期阻塞；不能让有依赖的控制通知无条件越序，也不能直接跨 Wasm 堆传递 SkPicture。 |

960×640 RGBA 一帧约 2.46 MB，47.6 FPS 对应约 117 MB/s 的单次整屏像素搬运量，尚未计入其他复制。这是 C1 和 C2 的动机，属于本地内存带宽，不能把它当作网络流量。

## SDK 优化与需要新增的 SDK

建议提供两组 SDK。Viewer SDK 负责嵌入、呈现和交互，服务端 SDK 负责 Session、任务和 Agent 工具。开发者通常不应直接处理 SKP、帧依赖或缓存协议。

| 编号 | 能力 | 应提供的契约 | 优先级和验收 |
| --- | --- | --- | --- |
| K1 | 稳定 Session API | 创建、连接、释放、TTL、并发配额、区域和版本；支持幂等创建与可查询操作状态。浏览器实例、Session、Page target、Agent run 分别命名。 | P0。超时重试不会多创建计费实例，过期 ID 无法复用到新页面。 |
| K2 | 可嵌入 Viewer | 原生 JS 组件为基础，React 包装可选；提供连接、销毁、只读、接管、resize、错误和性能事件。渲染资源与接入方页面 CSS 隔离。 | P0。任意宿主页面多次挂载卸载不泄漏；生产 CSP 与 iframe 嵌入 allowlist 可配置。 |
| K3 | 安全授权 | 后端 API key 与短时 Viewer ticket 分离；ticket 绑定租户、Session、角色、期限和 audience，支持撤销与刷新。 | P0。浏览器包里不放管理 key；read、control、Agent 执行权限可独立限制。 |
| K4 | 版本和能力协商 | 同时发布协议、渲染器、Wasm hash、Chromium 与 SKP 兼容表，按 capability 启用分块、GPU 和回退。区分可降级与必须拒绝的错配。 | P0。滚动升级期间新旧客户端可预测地连接、降级或拒绝，不出现随机错图。 |
| K5 | 输入与多角色控制 | SDK 返回明确的租约状态和 fencing token；租约覆盖所有可修改页面的工具，包括 Playwright/CDP 路径。 | P0。人工接管时所有受管 Agent 写操作停下；直接开放无限制 CDP 会绕过当前 `source.control.agent()`。 |
| K6 | 结构化观察与结果 | 为 Agent 提供受权限约束的 DOM/AX、元素定位、截图、文本和下载结果；附 target、epoch、观察时间与版本。 | P0。画面给人看，结构化观察给 Agent 用；页面更新后旧元素句柄不能静默作用于其他目标。 |
| K7 | 动作和业务成功分离 | 动作返回注入结果，再由调用方等待业务后置条件，例如 URL、DOM 状态、响应或订单 ID。对失败给可恢复、不可恢复和结果未知分类。 | P0。网络超时后不会自动重复付款、发信等动作；InputAck 不被视为业务成功。 |
| K8 | 取消与长任务事件 | 提供 AbortSignal、流式事件、心跳、重连游标、取消和资源清理；Webhook 带签名与事件 ID，接收方可去重。 | P0。断线后从事件游标续接，取消能明确说明哪些已执行副作用无法撤回。 |
| K9 | 开发者体验和发布 | TypeScript 优先，Python 紧随；稳定错误码、类型、示例、版本策略、文档、契约测试和本地运行方式。生成协议类型时保留实际验证逻辑。 | P1。开发者仅靠文档完成创建 Session、嵌入 Viewer、执行动作和获取结果，不依赖内部脚本。 |
| K10 | Agent 与文件集成 | 提供 Playwright/Steel adapter 和受权限约束的工具接口；上传下载、Profile 引用、任务结果和 trace ID 能关联。MCP 只是接入方式之一。 | P0 对实际首个 Agent，P1 对其他框架。不要为了支持所有框架而暴露完整不受管的浏览器控制面。 |

下面只是拟议的 API 形状，不是当前可调用接口：

for await (const event of client.runs.events(run.id, { after: cursor, signal })) {
  // 显示进度、人工审批或可验证的最终产物。
}

## 服务器和传输优化

| 编号 | 优化 | 具体改动与边界 | 优先级和验收 |
| --- | --- | --- | --- |
| B1 | 原生持续采集与按需订阅 | 当前每次通过 Runtime.evaluate 登记、Runtime.awaitPromise 等待，再用 Node 通知 Broker 映射和发布。增加浏览器内部受管订阅，原生以 frame token 发布；Node 保留启停、策略和输入控制。 | P0，高成本。保留输入与实际画面关联、取消、导航和 resize 屏障，不能只删 CDP ACK 后依赖跨 session 发送顺序。 |
| B2 | 更精确的时钟和消费需求 | 当前活动时约 60 Hz、空闲约 10 Hz、无 Viewer 停外部时钟。拆分 Viewer 显示、Agent 观察、录像和页面运行的需求，按真实消费方驱动。 | P0，中高成本。无人观看时不编码绘图流，Agent 等待 RAF、动画完成或视觉观察仍可推进；停采集不能被等同于冻结网页执行。 |
| B3 | 根据损伤与可见性选择 tile | 在现有 256×256 损伤录制上，增加可见区域优先、遮挡剔除、滚动附近有限预取，按内容与设备评估 tile 尺寸。 | P1，高成本。小 tile 降低局部重编码，大 tile 减少元数据；必须实际测总收益，保留跨帧损伤与缩放正确性。 |
| B4 | 字体与图片缓存平滑淘汰 | 当前字体和图片共享缓存达到字节或条目阈值时一起清空。改为分别计费的 LRU，预防大图片驱逐常用字体；复用正在进行的同键编码。 | P0，中成本。压力下冷缓存尖峰减少，缓存占用有界；不能在锁内进行重编码或等待另一线程。 |
| B5 | 减少新增 glyph 的重复工作 | 在保留源 Chromium shaping 和 glyph ID 的前提下，探索更稳定的字体分片或预热常见集合，减少流式新增文字反复生成整个子集。 | P1，高成本。中日韩、Emoji、variable fonts 与组合文字无错字；不能让客户端随意用系统字体重新排版。 |
| B6 | typed Scene 与端到端二进制元数据 | C++→Rust 的场景已有 RVB2，但 RPA2 仍含 JSON 描述，Rust 场景与 Viewer 场景也有 JSON。用类型化内部结构、紧凑 ID、变化字段和有版本的二进制 envelope 降低转换与重复字段。 | P0 或 P1，先测各消息字节占比。保留长度、数量、hash、依赖与解码预算校验；不是把已有二进制 IPC 再做一遍。 |
| B7 | 有界多帧流水线 | 当前 Gateway 只允许一个 inflight，客户端提交后才发 FrameAck。改为按字节和帧龄授予 credit，明确解码基线、显示基线和资源存活；对旧的可替代快照合并。 | P0，高成本。RTT 80 ms 下仍能稳定推进；缺依赖恢复、慢 Peer 和内存边界通过。绝不能简单删除 inflight 判断。 |
| B8 | 控制和大资源的优先级 | 初始字体、图片或关键帧不能长期阻挡接管通知和输入确认。建立控制优先队列、可见资源优先和有界块发送；必要时分离控制与资源连接。 | P0，中高成本。大图载入时控制仍及时；跨连接消息必须靠 epoch、序号和提交屏障确定顺序。 |
| B9 | 选择性压缩与帧打包 | 先统计场景、重复 hash、字体、图片、诊断字段各自占比。对适合压缩的数据用有上限的快速压缩，已压缩图片和小消息按阈值跳过；评估合并 SceneUpdate 与 FrameCommit 的发送开销。 | P0 测量，P1 编码。以 CPU、延迟和下行综合决策；不要无条件给所有 WS 消息开高等级压缩。私有压缩上下文不跨租户复用。 |
| B10 | 资源缓存的归属和回收 | 审计每个 host、layer、page epoch、字体、图片与 Broker 快照的缓存生命周期；按字节淘汰，保留关键资源引用，销毁 Session 时释放所属状态。 | P0，中成本。大量页面和 Session 创建销毁后内存回落；按条目数限制不能代替总字节预算。当前代码中的静态 host map 应重点覆盖长时测试。 |
| B11 | 降低 IPC 复制和写锁等待 | 已有常驻 socket 和后台写入。继续评估 scatter/gather、分块缓冲、独立有界 writer；大包拼接、锁等待和超时要有指标。共享内存只在复制确为主要成本时采用。 | P1，中高成本。保留完整消息边界、跨线程所有权和背压；不要把已有后台工作重新阻塞到 compositor。 |
| B12 | Gateway 事件驱动和共享计算 | 当前每 Peer 独立线程并以约 2 ms 读超时检查消息，连接上限为四个。规模扩大后使用事件驱动 IO、发布唤醒、共享编码及按 Viewer 基线缓存 delta，避免轮询和重复扫描。 | P1，中高成本。按 1、2、4 及目标连接数测 CPU、唤醒和帧龄，不能直接把四人上限调大当作扩容完成。 |
| B13 | 真实网站兼容与可用回退 | Viz 当前拒绝部分滤镜、非 SrcOver 混合和 3D 等情况。补 OOPIF、跨进程 Surface、视频、Canvas/WebGL、遮罩和 backdrop；先保证有明确错误或正确回退。 | P0 对首批客户网站，高成本。回退覆盖完整依赖区域；失败应保留可理解状态，不能挂着最后一帧让用户误以为仍在运行。 |
| B14 | 区域和传输部署 | 用同源 HTTPS/WSS 路由、短时授权、区域选择、连接健康检测和重连快照。当前 loopback URL、相邻端口和 CSP 是本地 harness 设计，上云需改为外部入口契约。 | P0，中高成本。代理、证书、负载均衡、长连接 draining 与真实公网测试通过；开启 host 绑定并不等于已完成云接入。 |
| B15 | 会话密度与调度 | 以实测 CPU、PSS/cgroup 内存、页面复杂度和排队指标分配 Session；预热浏览器或轻量隔离环境，支持配额、TTL、回收和有界重试。 | P0 对云服务，高成本。当前短窗口 RSS 会重复计算共享页，不能据此承诺一台机器容纳多少实例。 |
| B16 | 定制浏览器的持续维护 | 持续保存双架构构建缓存、产物来源、SBOM、依赖许可证、签名和回滚版本；定期升级 Chromium/Skia 并复跑兼容矩阵。 | P0 对发布，持续投入。当前 GitHub 双架构打包运行仍在进行，不能将工作流配置当作成品交付。 |
| B17 | 更快且更稳的 Session 首帧 | 当前 Source 等待 `page.goto(... networkidle)` 后才初始化捕获。对长连接或持续请求的真实网页，改用可解释的准备状态：导航已提交、捕获接口可用、首个场景可显示；网络静默只作为可选业务条件。浏览器与 Viewer 的准备可并行。 | P0，中成本。长轮询、流式页面和慢资源不会无限拖住 Session；首帧和任务可操作就绪分开衡量，不能为了快而宣称业务已加载完成。 |
| B18 | 减少服务器重复绘制 | 现有旁路记录与正常软件绘制共存。测量哪些服务器像素确实被合成、截图或 Agent 观察消费，再探索直接复用绘制记录、按需生成像素，或对合适负载启用服务器 GPU。 | P2，高成本。先验证是否存在可消除的重复工作；不能盲目关闭 raster、破坏 Viz 资源生命周期，也不能预设增加 GPU 后成本与延迟都会下降。 |

在单个 inflight 模式下，吞吐存在接近 `1 / (RTT + 客户端提交耗时)` 的串行等待上限。例如 RTT 80 ms、提交 5 ms，仅这一段就约 11.8 FPS，未计入其他环节。这个例子解释 B7 的优先级，不是公网实测数据。

流水线窗口的量级可从 `目标 FPS × RTT 秒数` 估算，再结合字节预算和实际解码时间调整。例如 60 FPS、80 ms RTT 至少需要覆盖约五帧的传输往返，但不能因此固定囤积五帧旧画面。旧帧合并、基线维护和资源释放必须一起设计。

WebTransport/QUIC 可作为 B8 和 B14 的后续实验，用独立流减少不同类型数据之间的阻塞；它不会消除 RTT、丢包或服务端工作。未可靠收到的字体、SKP 与增量依赖不能随意放在不可靠数据报上。WebSocket 仍应保留为兼容路径。

## 三十毫秒目标的合理范围

本机或低 RTT 环境，可以把真实像素 p50 小于 30 ms 作为下一轮实验目标，重点验证 C1、C2、B1 和帧调度。60 Hz 的每个刷新周期约 16.7 ms，源页面和客户端各错过一次时机，就可能消耗大部分预算。需要测帧龄和时序，而不只是优化编码函数。

公网真实画面闭环至少包含输入上行、服务器处理与结果下行。如果往返网络耗时已达 40 ms，整个操作便无法稳定在 30 ms 内完成。应分别承诺本地反馈、区域内远端像素和业务操作完成三个指标；选择就近区域、减少排队，并对可校正的编辑提供本地反馈。

不要预设 GPU 必然更快，也不要把并行线程数当作收益。小页面可能受启动、驱动和调度开销支配；帧已缓存时 font/image 耗时已经为零，此时继续增加编码线程没有帮助。

## 建议实施顺序与验收矩阵

1. **统一 trace 与网络实验。** 先把每段排队、工作和搬运区分清楚，收集消息字节分布；保存当前版本作为对照。
2. **客户端呈现。** C1 和 C2 分开实现、测量和提交，避免 GPU 与损伤算法同时变化后无法解释回归。
3. **公网交互。** C3、C10、B7、B8 按有版本协议推进，同时验证资源生命周期和旧租约拒绝。
4. **服务器关键路径。** B1 与 B2 减少逐次 CDP 控制，B4/B10 消除缓存容量悬崖，再依据数据做 B6/B9。
5. **产品接入。** K1 至 K8 与 B13 至 B16 对齐实际 Steel Session，形成可嵌入、可升级、可运维的服务。

| 维度 | 建议覆盖 |
| --- | --- |
| 网络 | 低 RTT、20/40/80/150 ms RTT，受限带宽，抖动、丢包、断线；分别记录实际 RTT 与工具配置值 |
| 页面 | 表单、长文档、表格、富文本、图片流、动画、跨域 iframe、滤镜、Canvas/WebGL、视频 |
| 生命周期 | 首次打开、预热、空闲唤醒、导航、resize、Profile 重连、Worker/GPU/Broker/浏览器失败 |
| 用户与设备 | 一人、两人、只读旁观、反复接管；桌面与实际移动设备，真实系统 IME |
| 性能 | 输入真实像素 p50/p95/p99、最大帧龄、首帧、FPS、带宽、每活跃小时成本、CPU、PSS/cgroup、Wasm/GPU 内存 |
| 正确性 | 图文及关键控件像素、字体与色彩、旧 epoch 拒绝、缓存缺失恢复、队列上限、无 Viewer 时的 Agent 继续运行 |
| 长时 | 至少 8 小时的目标工作负载；周期性创建销毁 Session、跨站导航、缓存淘汰和租约过期 |
