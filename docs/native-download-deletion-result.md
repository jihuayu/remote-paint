# Native BaseFile 取消删除结果

`BaseFile::CancelAndReportDeletion()` 同步关闭当前 BaseFile 持有的文件，然后返回 `base::DeleteFile` 的实际结果。空路径或文件已经不存在也视为成功；实际删除失败返回 false。原有 `void Cancel()` 委托这个方法并忽略返回值，保持既有取消、Detach 和析构行为。Android content URI 桥接仍执行原删除调用，但其接口没有删除回执，因此返回 false；本次未运行 Android 或 Mac C++ 验收。

这个接口只说明当前持有者关闭了文件并完成路径删除调用，不能用于宣称整个浏览器下载资源已经退休。独立测试明确证明：unlink 成功之后，另一个打开的文件句柄仍可持有 inode 并读取长度。真实 DownloadFile 异步任务、别名与文件身份、DownloadItem 删除、Playwright 元数据、预算保留与复用必须另外处理。实际删除失败后仍遵循既有 Detach 行为；调用方必须保留未结算状态并安排后续处理，不能把失败当作可复用预算。

新增7个真实文件系统用例覆盖未初始化路径、空文件、已写部分文件、完成文件、已被外部unlink的文件、非空目录导致的真实删除失败，以及其他持有者句柄仍然存在。失败用例通过替换路径为含子文件的非空目录产生真实 OS 删除失败，即使以 root 运行也不依赖权限模拟；目录内容不会被递归删除。完整 ARM64 ELF 未过滤52项（35上游、10既有写前限制、7新增）全部 RUN/COMPLETED，无失败、无禁用。

构建只使用自有 `out/RemotePaintDownloadBudget20261020v1` 的保留缓存。前置的15补丁全链重放、20实际文件、29拷贝组件及3份host配置验证已经独立封存；本次 prepare 在其明确补丁清单基础上应用第16个补丁并拷贝第30个组件。prepare 保持既有Ninja缓存身份，随后真实 GN 与 Ninja（23步）退出0。构建与测试容器均终态退出0、PID0、无OOM，随后删除；构建输出和Go缓存保留。
